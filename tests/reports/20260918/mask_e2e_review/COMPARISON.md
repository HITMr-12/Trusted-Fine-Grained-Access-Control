## 历史结论如何修订

| 议题 | 历史证据或判断 | 本次独立证据 | 修订后的结论 |
|---|---|---|---|
| 正常结果 | §14.2：72 次 MASK 摘要一致 | 历史记录重算成立；新 144 次正常查询摘要与历史参考一致 | **保留**特定查询的结果一致性；不外推授权或故障正确性 |
| 中高选择率性能 | §14.5：对 FGAC 中位优势约 26.5%–34.1% | 原 CPU 配置的 47.7%/100% 场景快 21.3%/30.4%；资源对齐组中高选择率快 31.5%–48.7% | **有条件保留**数据通路收益；不把不同轮次或资源组混成统一比率 |
| 低选择率稳定性 | §14.6：对 NATIVE 差不超过约 8.2%，场景可靠 | MASK2 在 0.1%/1% 比直接读取参考慢 17.3%/13.8%，并出现 12.198 秒样本 | **缩小适用边界**；小样本不支持跨资源条件的固定上限 |
| 公平性 | §13.2：除方案差异外全部对齐 | MASK 不验身份/策略；最新 NATIVE 普通 conf 未启用 Ranger；启用 native-conf 后拒绝检查通过 | **不认可安全等价比较**；计时 NATIVE 只能标为原始读取参考 |
| 可靠性 | §14.3/14.6：断连处理、三类选择率可靠 | 真实链路在首个完整文件后断连仍成功输出 970,294 行；空流使消费进程退出 | **否定全场景可靠判断**；正常摘要不能替代失败语义验证 |
| 网络字节优势 | §14.6 引用 VPN 口径约 1.2 MB 控制流 | 当前 R→E 每次实际投递 806,898,847 字节净载荷，所有选择率相同 | **修正口径**；不把控制流、旧压缩路径和当前数据流混用 |
| 串行生产影响 | §15.2 通过 R/E 分段耗时推导串行端到端基本不变 | MASK1 三场景完整 E2E 中位数 9.841/10.174/11.121 秒 | **原推导不足**；补测非同轮配对，不宣称严格并行度因果收益 |
| 可复现性 | 固定代码与远端部署被视作同一状态 | 缺失 phase1 helper，部署白名单有额外一行，背压需单独应用 | **补充部署前提**；保留显式修补和首次失败记录 |

新证据只覆盖单客户端、固定五列和当前 32 文件布局。普通 conf 与 native-conf 的拒绝检查只用于定位授权配置差异；本次没有将启用 Ranger 后的性能冒充已测结果。

## 如何比较数字

- 原报告 72 次 MASK 与较早的 NATIVE/FGAC 各 3 次参考并非同轮交错，算术正确不等于实验完全公平。
- 本次资源对齐组与原 CPU 配置组分别报告，各场景各模式 3 次正式重复，预热不进入中位数；有效离群值全部保留。
- MASK1 后续补测单列。旧报告 E 端单段读副本耗时、分段求和与本次完整端到端耗时不放在同一性能表中。
- 本次未修复 MASK 业务代码。报告列出的授权、协议和通用性问题仍是待修复项。

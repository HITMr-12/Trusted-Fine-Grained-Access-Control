## 结论和限制

存在其他业务与后台活动，且压缩测试时 R 端背景 CPU 活动较上一轮明显增加；尚无证据证明其导致两轮性能差异。整机远未 CPU 饱和，历史 iowait 很低，当前也无明显资源压力。不能据此排除短时单核、缓存、内存带宽或网络竞争。

历史采样没有全进程榜单、每核调度等待、PSI 与磁盘延迟，因此无法事后识别哪个进程影响哪条查询。当前活跃进程不能直接当作历史干扰源。当前进程 CPU 差分只覆盖两端快照都存在的进程，短命进程可能遗漏。E 当前已有 swap 占用不等于正在换页，未采集换页速率。

下一轮建议在固定预热和查询顺序口径下，增加同步全进程 CPU/I/O、每核利用率、PSI、网络及磁盘采样，对齐每条查询时间；保留全部样本并事先约定异常负载判据，通过多轮独立重复确认稳定性。无需限制 FGAC 计算资源或停止既有服务。

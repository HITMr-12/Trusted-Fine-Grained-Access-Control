# 并行度弹性实验（实验 D）：为 Arrow 字节直通（方案 A）定标

日期：2026-09-17　对象：bench_full_1_0（28.8M 行，100% 选择率），FGAC Arrow 路径

## 结果（total_ms 中位数，warmup 1 + 5 reps，单 worker 探测）

| R 端并行度 | total_ms | 对 local[2] 基线 |
|---|---|---|
| local[2]（既有基线） | 14,239 | 1.00× |
| local[4]（18837） | 14,638（13,512–14,687） | 1.03× |
| local[8]（18838） | 14,563（13,469–14,976） | 1.02× |

## 结论

**零弹性**：R 端核数 2→4→8，端到端无任何改善。3.8ms/MB 的税**不是扫描并行度不足**，而是单线程 Python Flight 序列化环路的每字节成本（6 跳链中 ②③④⑤ 的物化往返）+ E 端消费速率。加核对税无效。

## 决策含义

1. **方案 A（Arrow 字节直通）的收益不会被核数卡住**：税的主体是按字节计费的 Python 物化工作，把 6 跳压到 3 跳（引擎序列化 → 纯字节搬运 → 引擎反序列化）后，预期税从 3.8 降到 ~1.2ms/MB，FGAC 从 1.51× 收敛到 ~1.2×。
2. **"加机器"这条路被证伪**：可信网关的部署成本优化只能走减少每字节工作量，不能走堆核。
3. 本实验同时反向验证了选择率基线的稳定性：单 worker 探测（14.5s）与交错基线（14.2s）一致。

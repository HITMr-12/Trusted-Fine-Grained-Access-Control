# 掩码通路端到端四方案对比：zstd 存储 + 解压掩码不重生（先验 footer）

日期：2026-09-17　数据：TPC-DS store_sales 28,800,991 行（5 列投影，28 B/行）
对局：NATIVE（直连）/ INLINE（行过滤内联）/ FGAC（现有 Arrow 通路）/ **MASK（本方案：zstd 存储 + R 端解压字节掩码 + 不重生 + 标准 Parquet 投递）**
case 与业务谓词完全复用 `选择率基线报告.md` 的 8 点（`ss_sales_price >= 阈值` 控选择率），NATIVE/INLINE/FGAC 数字直接引用该报告（同日实测，口径一致）。

## 0. 结论（先看这里）

1. **时间轴上 MASK 全面落后**：端到端（R 生产 + 传输 + E 引擎）内网折算 18.8–24.0s，在全部 8 个选择率上都慢于 NATIVE（3.9–10.0s）、INLINE（4.0–10.9s）和 FGAC（3.9–15.0s）。落后的根源不是掩码本身，而是**投递必须无压缩**（字节级保留要求）导致 **E 端必读 806MB 无压缩 Parquet，比直读 275MB zstd 源慢 6.7–8.0s**，且该成本与选择率无关（固定税）。
2. **字节轴上 MASK 占优**：投递字节恒定 806.5MB（FGAC 从 1.4MB 线性涨到 1,512MB），传输层再经 zstd 压缩后实传 **1.2–239MB**，8 个点全部低于 FGAC 的线上字节；≥57.5% 选择率时投递字节也开始低于 FGAC。
3. **编码次数最少**：全链路仅 1 次 zstd 解码（R）+ 引擎内 1 次 Parquet 解码（E），**零次编码/零重生**；对照 FGAC = 扫描解码 + Arrow 编码（R 端 ipc_write）+ Arrow 解码（E）。
4. **"不重生掩码"作为时间最优解被定量关闭**：其 E 端固定税（~7s）超过 FGAC 的最高税额（4.9s@100%），且没有任何不破坏"字节保留"的出路（压缩重生已被判负 13.3–14.2s；随机分布下页级全放行分流概率为 0）。二期优化方向因此钉死在 **L1 聚簇授权布局**（让 E 只读授权分片，而非读全量再过滤）。
5. **流式成立**：R 生产以文件级粒度（~25MB/文件内存上界）边产边传，三案实测管道 wall 10s/87s/107s（VPN），产物与批量模式逐字节一致（sha1 校验）。

## 1. 方案要点（MASK）

- **存储**：zstd 压缩 + PLAIN（禁字典）+ 统计量开启（泄露暂忽略），275MB / 32 文件。
- **先验 footer（本次实现的核心机制）**：投递布局（无压缩页结构）对给定源文件是**查询无关的确定性产物**——页头里 `uncompressed = compressed = nvals × width`，footer 结构固定。因此一次性预计算 per-file **骨架**（每页的行区间 + 页头字节原样 + footer 字节），查询期 **零 thrift 簿记**：只做 解压 → 位图 memset → 按骨架拼装 → 发送。骨架大小：32 文件 × (26 页 + 1KB footer)。
- **字节序事实（已验证）**：普通 int 列 PLAIN 为**小端**；`decimal(7,2)` 物理 int32 为**大端**无标度值。掩码哨兵 -1（全 FF 字节）两端序通用。R 端位图与参考 digest 直接由解压字节的 numpy 视图算出，**生产路径零 Parquet 解码**。
- **正确性**：8/8 case E 端 Spark digest（注入业务谓词后 rows + 5 列 sum/min/max）与 R 端参考全等，行数与基线表逐案对齐（27,668 / 275,793 / 2,752,030 / 13,752,062 / 16,550,273 / 20,686,229 / 24,773,691 / 28,800,991）。掩码只发生在副本/流，物理源文件未动；E 端必须注入策略谓词，掩码行（price = -1.00）自动被过滤，不会打印无效数据。

## 4. 传输与流式

投递字节恒定 806.5MB（掩码不缩容，这是"不重生"的对价）；传输层 zstd 压缩后与选择率强相关（掩码行是哨兵长程，压缩极快）：

| case | zstd 传输字节 | VPN @2.75MB/s | 流式管道 wall（实测） |
|---|---|---|---|
| s001 | 1.2 MB | 0.5s | **10s**（生产受限） |
| s01 | 7.8 MB | 2.9s | （未单独实测，插值 ~11s） |
| s10 | 54 MB | 20s | （插值 ~28s） |
| s477 | 184 MB | 67s | **87s**（传输受限） |
| s575 | 206 MB | 75s | （插值 ~95s） |
| s718 | 229 MB | 83s | （插值 ~105s） |
| s86 | 239 MB | 87s | （插值 ~109s） |
| s100 | 229 MB | 83s | **107s**（传输受限） |

- 流式粒度 = 文件（~25MB），R 生产/传输/E 落盘三段在单管道内重叠；s001 管道 wall 10s ≈ R 生产 7.6s（生产受限），s477/s100 wall ≈ 传输字节/2.2MB/s（传输受限）。
- **内网 10GbE 下传输 0.7s（未压缩投递）或更短（压缩传输），永远不是瓶颈；瓶颈在 R 生产（4.3–7.8s）与 E 引擎（10.6–17.6s）。**
- 流式产物与批量产物 **sha1 逐文件一致**（s001/s477/s100 三案校验通过），证明流式分帧无损。
- VPN wall 是测试环境的带宽假象，报告中的 e2e 一律以内网折算为准，VPN 实测仅证明流式机制成立。

## 5. 逐轴对比

### 5.1 时间轴：MASK 全区间第 4

分解 MASK 的落后来源（以 s001 与 s100 为端点）：

| 成分 | s001 | s100 |
|---|---|---|
| R 生产 | 7.5s | 4.3s |
| E 引擎（读 806MB 无压缩投递） | 10.6s | 15.7s |
| 传输（内网） | 0.7s | 0.7s |
| **合计** | **18.8s** | **20.8s** |
| 对照 FGAC 合计 | 3.9s | 14.5s |
| 对照 NATIVE 合计 | 4.0s | 9.6s |

- **E 端固定税 = MASK E 引擎 − NATIVE ≈ 6.7s（0.1%）～ 8.0s（约 47.7% 平台后收敛 ~6s）**。根源：806MB 无压缩 vs 275MB zstd 的磁盘读 + 解码放大（2.9× 字节），且业务谓词在两端都无统计可下推（随机分布）。
- FGAC 的税是"字节税"（3.2–3.9ms/MB × 线上字节），随选择率线性涨；MASK 的税是"固定税"（~7s）。**两条税线在实测区间内不相交**——即便 FGAC 在 100% 选择率达到最大税 4.9s，仍低于 MASK 的固定税 ~7s。

## 6. 口径与局限（诚实声明）

1. **E 引擎环境差异**：MASK 的 E 引擎用 `mask_digest_e.py`（fgac-current 的 SPARK_CONF_DIR，local 模式）；基线三模式用 `selectivity_bench.py` 的 local[2] + 3 worker 交错中位数。E 引擎绝对值与基线 total 不完全同口径，但 E 读 806MB 无压缩投递的 10.6s 下限本身是实测硬值，不改变相对排名（即便给 MASK 抹平 7s Spark 启动差，18.8s vs 3.9s 的差距仍在）。
2. **E 引擎随选择率上升**（10.6→17.6s）是因为谓词通过率越高，filter 后续算子（count+agg）处理的行越多；100% 反而略降（无 filter 算子，whole-stage 更优）。
3. **参考 digest 依赖 R 端先验位图**：位图 3.6MB/查询 未计入投递字节（与基线 FGAC 的谓词列回传记账方式一致）。
4. s01/s10/s575/s718/s86 的流式 wall 为按压缩字节的插值，非实测。
5. 统计量开启的泄露按既定决策暂忽略；掩码哨兵 -1 与 NULL 填充哨兵 -2 在交付列中可区分（背景信息泄露）是接受的已知代价。

## 8. 对二期的定量指引

1. **关闭的路线**：压缩重生（+13.3–14.2s 已判负）、不重生掩码作为时间解（固定税 ~7s > FGAC 最大税 4.9s，本报告）。字节通路（分帧重编码）此前已判负。
2. **唯一开放的时间轴路线：减少 E 必读字节**。L1 聚簇授权布局（授权行物理聚集）让 E 只读授权分片：在 90% 权限 + 高选择率场景，E 读量可从 806MB 降到 ~90% 分片甚至更低，固定税随分片数线性消失。配合 sidecar 页表做页三级分流（全放行页直通原 zstd 字节 → 连解压都省）。
3. **若放弃时间轴、只保字节轴**：MASK 是当前编码次数最少、引擎无关的恒定 806MB 方案，适合"高选择率 + 带宽受限 + 异构引擎"的部署画像。

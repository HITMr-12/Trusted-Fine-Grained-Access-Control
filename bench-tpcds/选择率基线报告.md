# 选择率基线测试报告：现有最优方法（FGAC Arrow 路径）vs NATIVE / INLINE

日期：2026-09-17　数据：TPC-DS store_sales 28,800,991 行　协议：3 常驻 worker 同机交错，每 (case, rep) 按 6 排列轮转消序，warmup 1 轮 + 正式 8 reps（192 条正式记录）；逐条 digest 断言：旧 case 对 NATIVE 参考全等，新 case 三重跨模式全等——全部通过。

## 测试对象

"查询可达全量数据"：bench_full 主体**无授权行过滤**（row_filter = null），选择率完全由业务谓词 `ss_sales_price >= 阈值` 控制。高选择率段按 12:44 指示加密：由 `approxQuantile` 取阈值并实测精确行数，新增 57.5% / 71.8% / 86.0% 三点。

## 发现

### 1. FGAC 开销随选择率单调增长，封顶 ~1.51×

FGAC/NATIVE 从 0.99×（0.1%）单调升至 1.51×（86%–100% 平台）。可信网关架构的代价不是常数，而是与回传字节量成正比。

### 2. 税额验证：3.2–3.9 ms/MB，与税模型吻合

FGAC − NATIVE 的差值 ÷ 线上字节：

| 选择率 | (FGAC−NATIVE) | 字节 | 单位税 |
|---|---|---|---|
| 47.7% | 2,748 ms | 720 MB | 3.8 ms/MB |
| 86.0% | 5,065 ms | 1,298 MB | 3.9 ms/MB |
| 100% | 4,857 ms | 1,512 MB | 3.2 ms/MB |

与 0916 压缩 A/B 测得的 **3.8 ms/MB** 端到端 CPU 搬运税一致。税额模型成立：**FGAC 附加成本 ≈ 线上字节 × 3.8ms/MB**，而线上字节 ≈ 行数 × 52.5B（五列投影 Arrow）。

### 3. 固定地板 ~3.9s：低选择率下可信架构"免费"

0.1%–1% 选择率时三模式无差别（3.9–4.1s）——这是 28.8M 行全表扫描 + 摘要的 E 端地板（local[2]），此时 FGAC 的 R 端扫描、KB 级传输全部被地板吞没。**选择率 ≤1% 时，FGAC 相对直连基线零代价**；R/E 分离的可信架构在这个区间是纯收益。

### 4. INLINE 恒介于两者之间

INLINE（行过滤内联进 WHERE，无 Ranger 插件、无 R 跳）FGAC/INLINE = 0.97×–1.38×：它比 FGAC 便宜（无 Arrow IPC 税），但比 NATIVE 贵（内联过滤表达式 + 全表扫描不变）。它标出了"过滤执行位置"的代价带宽：FGAC 比 INLINE 贵的部分（高选择率时 ~1.3×）就是 Arrow 通路的净税。

## 对后续优化的含义

1. **收益折算公式**：任何降低线上字数的机制（聚合下推、授权列裁剪、直通），收益可直接按 `Δ字节 × 3.8ms/MB` 折算。例：86% 选择率下 partial aggregate 下推把 1,298MB 压到 KB 级，预期 FGAC 从 15.0s 降到 NATIVE 地板 ~10s 以内。
2. **主攻场景重新定位**："90% 权限 + 随机分布 + 高选择率"恰是税最重的区间（1.5×）；而低选择率区间现有方案已最优，无需投入。
3. **字节通路（分帧重编码）的判负与基线自洽**：它想把 1,512MB 换成 333MB（省 ~4.5s 税），但 R 端重编码 +15.8s 关键路径，净亏——与选择率曲线中"字节税 3.8ms/MB 可省上限 ~4.5s"的估算完全吻合。

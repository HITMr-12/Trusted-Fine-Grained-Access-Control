# 页级短路机制可行性实测（2026-09-17）

## 背景

假设的机制：对过滤列逐 Page 判定，若"整页同值且命中等值谓词"（ColumnIndex `min==max==目标值`）则原始 Parquet 字节直发（不解码不过滤），跨界页走 Arrow 过滤；顺序不保证。

## 关键修正：数据实况

- 之前"页索引腐坏"结论是**假象**：直接读 MinIO 后端 `part.1`（29,205,080 B）与 S3 对象（29,204,184 B）**差 104 字节**，后端文件不可用于解析；
- 经 S3 接口读取的活数据完全健康：parquet-mr 1.13.1 写出，ColumnIndex 23/23 可读，RG 级统计 23/23，pyarrow/vanilla reader 均可读；
- **教训：一切 Parquet 分析必须经 S3 接口取对象，不得直读 MinIO 后端文件。**

## 实测 3：页大小扫描（排序数据，解析模拟）

| 页行数 | 约页大小 | 常量页占比 |
|---|---|---|
| 19,500（现状） | ~550KB | **0%** |
| 8,000 | ~230KB | 46.1% |
| 4,000 | ~115KB | 70.7% |
| 2,000 | ~57KB | 83.2% |
| 1,000 | ~29KB | 89.4% |
| 500 | ~14KB | 92.5%（天花板 = 门店边界） |

## 结论

1. 机制天花板 = `1 - 每页不同值数`，由**数据聚簇度 × 页大小**共同决定，与文件格式无关；
2. 当前 bench 数据（无序 + 大页）：**收益为零**，不值得实现；
3. 可行前提："按授权过滤列聚簇存储"（数据湖常规 z-order/sort-by 布局）+ 小页（1–2k 行，64–128KB）→ 上限 83–92% 页直发；
4. 小页代价：页头/元数据开销上升、压缩率微降（待实测量化，预计 <5%）；
5. 与此前结论的关系：本机制是"存储布局 × 授权短路"的叠加优化，与聚合下推正交；对当前 digest 负载，聚合下推仍是收益最大项。
